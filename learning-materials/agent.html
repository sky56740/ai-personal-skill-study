Agent LLM 应用范式

一个人格化的目标执行体：能感知、规划、调工具、迭代到完成。

我的理解：Agent并不是只会问答的聊天机器人。普通大模型只回答当下提问；Agent可以自己拆分任务，一步步调用工具，直到完成整套目标。

1. 一句话定义

Agent = 以 LLM 为大脑，能自主"感知环境 → 规划 → 调用工具 → 执行动作 → 评估结果"， 围绕一个目标循环工作直到完成或放弃的程序系统。

它不是单一模型调用，而是一段循环执行的智能流程。

2. 核心机制 / 组成

① 感知 Perception

读入任务、用户输入、当前环境状态。

② 规划 Planning

LLM 把目标拆成步骤，决定下一步做什么。

③ 工具 Tool Use

调用搜索、计算、API、文件、代码执行等外部能力。

④ 记忆 Memory

短期对话历史 + 长期记忆库（向量库、笔记、Key-Value）。

⑤ 动作 Action

真正改变世界：写文件、发邮件、改数据库、提交 PR。

⑥ 反思 Reflection

评估动作结果；失败则重新规划，进入下一轮循环。

一个最小 Agent 可以只跑 规划 → 工具 → 反思 三步循环；复杂 Agent 通常还引入 Planner/Executor/Critic 多角色协作。

3. 一个具体应用场景

任务：让我写一份"3 家咖啡品牌"的竞品分析报告。

  1. 输入：用户说"帮我分析 Manner、%Arabica、Seesaw 的定价和门店扩张"。
  2. 规划：Agent 拆成"搜定价 → 搜门店数 → 拉近 1 年新闻 → 对比 → 写报告"。
  3. 工具调用：浏览器搜索 API、官网抓取、Excel 写入。
  4. 反思：发现 1 家门店数数据缺失，重新搜一次。
  5. 输出：一份 Word/HTML 报告 + 一张对比表。

这一类流程如果用纯 chatbot 写，要用户在窗口里反复复制粘贴； 用 Agent 端到端跑完，人只在最终审核。

4. 容易混淆的问题与使用边界

  • Agent ≠ Chatbot：chatbot 只"说话"，agent 会"做事"——能不能调用工具、能不能改环境，是分水岭。
  • Agent ≠ RPA/传统自动化：RPA 是写死流程的脚本；agent 的下一步由 LLM 决策，可控性弱但适应性高。
  • LLM ≠ Agent：LLM 是大脑，agent 是大脑+双手（工具）+记忆。直接调一次 ChatGPT 接口不是 agent。
  • Agent 不等于 AGI：AGI 强调能力广度；agent 是当前工程上的一种实现路径，可能很"窄"。
  • 多 Agent ≠ 多步骤：多 agent 是多个独立智能体互相通信；多步骤是单 agent 自己顺序执行。
  • 使用边界：高风险动作（付款、删数据、发公开消息）应当被人审批，不要让 Agent 完全自主。

5. 自测问题

Q1. 区分 Agent 和 Chatbot 最关键的指标是？

是否能调用工具、是否能执行动作并改变环境，而不只是生成文本。

Q2. 一个最小 Agent 至少包含哪几个组件？

LLM（推理）+ 工具调用能力 + 反思循环。

Q3. 哪些场景不适合让 Agent 完全自主？

涉及金钱、隐私、生产环境删改、对外公开发布等高风险动作，需要人在回路（human-in-the-loop）。

Q4. 为什么不能简单把 "LLM + 几行 prompt" 叫做 Agent？

因为没有"循环执行 + 工具调用 + 反思"的机制，它只是一次性问答，不构成目标驱动的执行体。
